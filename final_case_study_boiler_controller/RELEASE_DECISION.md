# Release Decision — Smart Boiler Safety Controller

## Build / Version
BUGGY builds підсистем (стенди тижнів 1–7), Wokwi for VS Code + PlatformIO; оцінка станом на 01.11.2026.

## Executive Summary
Контролер виконує основні функції в happy path: читає датчики, керує реле і PWM, відповідає на CLI, переживає зависання завдяки watchdog і відновлює мережеве з'єднання (60/60 reconnect).
Але головна вимога безпеки не виконується: після аварійного reset, power loss або команди RESET нагрів може залишатися ввімкненим, відмова датчика маскується під 0.0 °C, а збій I2C-датчика заморожує контролер без відновлення.
Додатково — шум на кнопці вмикає дію, телеметрія губиться і дублюється, пам'ять витікає з кожним повідомленням.
Рішення: **NO-GO**.

## Residual Risks
- Підсистеми не перевірялись в одній інтеграційній збірці.
- Не перевірено на реальному ESP32: brown-out, NVS при фізичній втраті живлення, реальний дребезг і наводки, реальні Wi-Fi / MQTT.
- Таймінги Wokwi відрізняються від реального часу.
- Довготривалий прогін (доби) не виконувався.

## Rationale
GO WITH RISKS допустимий лише тоді, коли відкриті ризики не стосуються безпеки і даних та мають обхідний шлях. Тут відкриті Critical-дефекти саме в safety-функціях (R05, R03, R04, R07) — для котла це неприйнятно незалежно від кількості пройдених тестів.

**Умови для повторної оцінки:**
1. Виправлено всі Critical; fail-safe на старті: виходи OFF до валідного вимірювання.
2. Повна регресія: pytest-набір, run_scenarios.py (3 прогони), scenario.yaml ×5, hang / powerloss ×5, I2C FAULT з PulseView.
3. Інтеграційна збірка всіх підсистем на одному стенді.
4. Валідація на реальному ESP32 зі списку Residual Risks.
