# Webinar 2 — GPIO / Interrupt / Button Debounce

ESP32 у Wokwi: BUTTON (кнопка з дребезгом) і NOISE (штучні короткі імпульси) на GPIO18, LED логічної події на GPIO2, Logic Analyzer (D0 — RAW вхід, D1 — логічна подія) і вбудований Serial Logger: фізична дія → RAW-переривання → логічна подія → дія.
Головна вимога: одне натискання = одна подія = одна дія; шум і дребезг не створюють зайвих подій.

## Файли

| Файл / папка | Що всередині |

Запуск сценарію: `wokwi-cli --scenario scenarios/s2_noise_5ms.yaml --timeout 30000 <папка проєкту>`.

## Результати

| Тест | Сценарій | Результат |
|---|---|---|
| TC-01 | Звичайний натиск | PASS 5/5 |
| TC-02 | Один натиск у Logic Analyzer | PASS |
| TC-03 | Утримання 3 с | PASS 3/3 |
| TC-04 | 5 окремих натискань | PASS 3/3 |
| TC-05 | Імпульс шуму 5 мс | FAIL 5/5 — BUG-01 |
| TC-06 | Шум під час критичної операції | FAIL 5/5 — BUG-02 |
| TC-08 | Heavy bounce 2 мс × 7 | FAIL 5/5 — BUG-03 |

| ID | Дефект | Severity |
|---|---|---|
| BUG-01 | Імпульс шуму 5 мс приймається як натискання і запускає дію | High |
| BUG-02 | Шум під час критичної операції створює другу подію і другу дію | High |
| BUG-03 | При сильному дребезгу подія приймається на першому перемиканні, до стабілізації входу | Medium |

Рішення: **NO-GO** — вхід не перевіряється на стабільність, подія приймається з першого RAW-переривання.

## Оновлення після рев'ю
- Шум під час критичної операції перепрогнано з Serial Logger: PASS → FAIL 5/5 (BUG-02).
- Відтворюваність підтверджена файлами: кожен проблемний сценарій запущено 5 разів, кожен прогін збережено в `logs/`.
- Кожен тест — окремий сценарій без `wait-serial`, тож прогін більше не зависає на застарілому номері події.
- TC-02…TC-04 мають Serial Logger; D1 рахується за одним правилом (фронт вгору = подія); додано рисунок з VCD.
- Дефекти з одного звіту розділено, у кожного є severity; висновок переписано з рішенням NO-GO і рекомендаціями.
- Нумерація приведена до `test_cases.md` курсу (heavy bounce: TC-06 → TC-08; шум під час операції: TC-07 → TC-06).
